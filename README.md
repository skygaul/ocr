# Census Table 1 — 표 이미지를 검색·복사 가능한 표로 (선택 과제 B)

1910 인구조사 보고서의 Table 1(면적·인구) 이미지를 PaddleOCR로 읽어 `table.csv` / `document.md`로 복원하고,
원본과 대조한 수정·확인 기록을 남긴다. 추가로 칸을 클릭해 검토하는 웹 화면을 제공한다.

- 출처: U.S. Census Bureau, 1910 Census report(1913 발행), PDF 2쪽 · 인쇄 22쪽, 미국 연방정부 발행 퍼블릭 도메인 자료(과제 안내 기준)
- 입력: `input/census-table.png` (200 dpi, 과제 제공 이미지)

## 실행 방법
실행 위치: **로컬 PC (Windows 11, Python 3.13, CPU 전용)**. 이미지는 외부로 전송되지 않는다(모델은 최초 1회만 내려받음).

```bash
pip install -r requirements.txt
python run_ocr.py                 # OCR + 표 복원 + 문서 생성 → outputs/ocr/
python run_ocr.py --table fraser  # FRASER No. 11 (결과: outputs/ocr-fraser/)
python run_ocr.py --build-only    # OCR은 건너뛰고 corrections.json 반영해 표/문서만 재생성 (--table fraser 와 함께 사용 가능)
python app.py                     # 웹 서비스 → http://127.0.0.1:5000 (/review?table=census|fraser = 표 검토 화면)
```

## FRASER No. 11 (두 번째 표) 결과 — `outputs/ocr-fraser/`
- 구조: 캡션 3줄 + 묶음 제목(Maturity) + 8열 + 본문 48행(구역 소제목 2줄 포함) + 각주. 행마다 `Total = 만기 구간 합` 검산(48건).
- 원시 OCR에서 합계·날짜 순서 검산이 잡아낸 오류와 원본 확대 대조 결과:

| 칸 | 원시 OCR | 원본 | 발견 방법 |
|---|---|---|---|
| R9C2 Sept. 26, Within 15 days | `13,707` | `13,767` | 행 합계 +60 불일치 → 한 자리 힌트 → 확대 대조 |
| R3C0 날짜 | `Mür. 28` | `Mar. 28` (a가 인쇄 손상) | 신뢰도 0.86 + 날짜 순서 불일치 |
| R23C7/R24C7 Over 6 months | `28`(한 칸) | `2`와 `8` | OCR이 세로로 붙은 두 숫자를 한 박스로 읽음 → 분리 후 행 합계로 확인 |
| R26C0 날짜 | `1934Jan.31` | `1934—Jan. 31` | 줄표 누락(구두점) |
| 캡션 C0/C1 | `—-`, `1934-35` | `—`, `1934–35` | 구두점만 수정 |

- 합계 불일치가 한 행뿐이라 오류 위치를 좁힐 수 있었지만, 합계가 우연히 맞는 오류나 합계에 걸리지 않는 라벨 글자는 규칙으로 못 잡는다. 대조 기록이 없는 `auto_ok` 칸(335개)은 규칙 통과일 뿐 사람 대조가 아니다.
- 칸 51개는 원본에 숫자가 아닌 점선이 인쇄된 빈 칸이다(`source_empty`, 행 합계가 맞아서 자동 판정). 추정해 채우지 않았다.

## 도구·설정 선택 이유
- **PaddleOCR(영어 모델)**: 과제 요구. 처음엔 한국어 모델로 돌렸더니 `Table 1→able 1`, `1910→1010`, `3,435→B,435`, `Outlying possessions→possesgions` 같은 오인식이 났고, 영어 모델(PP-OCRv6)에서는 모두 사라졌다. 영어 표라서 영어 모델을 최종으로 썼다.
- **`enable_mkldnn=False`**: Windows CPU에서 oneDNN 오류(`ConvertPirAttribute2RuntimeAttribute`)가 나서 껐다.
- **좌표+가로 괘선 기반 표 복원**: 글자 박스의 x·y 간격으로 행·열을 나누고, OpenCV로 찾은 가로선으로 캡션/머리글/본문 경계와 묶음 제목(Maturity)을 구분했다. 표 구조 모델(PP-StructureV3)은 모델이 크고 설정이 까다로워 쓰지 않았다.
- **표 아래 캡션 제외**: 이미지 맨 아래의 `FRASER No. 11 — …` 한 줄은 표가 아니라 웹페이지 캡션이라 잘라냈다(crop 좌표는 manifest에 기록).
- **합계 검산 규칙**: 미국 전체 = 속령 제외 + 속령, 속령 = 8개 지역 합. 원본의 합계 구조를 이용해 오인식 칸을 찾는 단서로만 쓴다(값을 자동으로 고치지 않음).

## 확인 필요로 남긴 부분
현재 미해결 `needs_check` 칸은 없다(`manifest.json`의 `status_counts` 참고). 다만 아래는 한계로 명시한다.
- 원본 대조는 **코딩 에이전트(Claude)가 이미지를 보고 1차로 수행**했다. 제출자(사람)의 재확인이 필요하며, 의심 가는 칸은 `/review`에서 "확인 필요로 표시"하면 `table.csv`의 `needs_check` 열과 `document.md`에 반영된다.
- 위첨자(¹ ²)는 200 dpi에서 작아 육안 판독이 어려워 합계 검산(총합 일치)을 보조 근거로 썼다.
- 헤더 `in square miles.`의 끝 마침표처럼 구두점은 정리 과정에서 제거된다.

## 처음 예상 vs 실제 (작성 시점 기록)
- 예상: 낡은 인쇄의 쉼표·`0`/`O` 혼동과 들여쓴 행의 열 어긋남.
- 실제: 영어 모델에서 쉼표·`0`/`O` 문제는 거의 없었고 행·열 어긋남도 없었다. 오히려 **위첨자 각주 번호가 숫자에 붙는 문제**와, 신뢰도가 높은데도 틀린 **각주 연도(1012)** 가 핵심 오류였다. 점수·합계 같은 자동 검증만으로는 부족하고 원본 대조가 필요했다.

## 웹 서비스 화면 설계
- 상태는 색과 모양을 함께 쓴다: ⚠ 확인 필요(빨강) · ✎ 수정함(주황) · ✓ 원본 대조 일치(초록, 사람이 확인한 칸만) · • 규칙 통과(회색, 대조 기록 없음) · — 원본에 값 없음(보라).
- 공용 스타일은 `static/app.css`(색·서체·간격 토큰, 라이트/다크). 복원 표는 원본 인쇄물처럼 세리프 + 점선 리더, 숫자는 우측 정렬(tabular-nums).
- 검토 화면: 위에 상태 요약 막대, 왼쪽 원본(고정), 가운데 표, 오른쪽 편집창. 1000px 이하에서는 편집창이 아래 시트로 열린다. 칸은 Tab/Enter로도 선택, Esc로 닫는다.
- 오른쪽 위 테마 버튼으로 자동(시스템) → 라이트 → 다크를 전환하고, 선택은 이 브라우저에 저장한다(`static/theme.js`). 주소 뒤에 `?theme=dark|light`를 붙이면 저장 없이 임시로 강제할 수 있다.

## 웹 서비스
(범용 표 복원: 이미지의 가로 괘선을 찾아 캡션·묶음 제목(예: Maturity)·열 제목·본문·각주를 나누고, 본문 글자 간격으로 열을 추정한다. 세로로 붙어 한 박스로 읽힌 숫자(예: `2`+`8`→`28`)는 줄 수만큼 분리하고 경고를 표시한다.)
- `/` : 임의의 이미지 업로드 → OCR → 텍스트/표 복원 → TXT·JSON·XLSX·CSV 다운로드 (결과는 `results/`, `uploads/`에 저장)
- `/review` : Census Table 1 검토 화면. 칸 클릭 → 원본 위치 강조, 원시값·사유·힌트 확인, "원본과 일치 / 값 수정(근거 필수) / 확인 필요 표시" → `corrections.json` 갱신 후 `table.csv`·`document.md` 즉시 재생성
